Governed multi-agent software engineering

One outcome. Isolated agents. One reviewable result.

MC-GPT coordinates Claude Code, OpenAI Codex, Gemini CLI, Grok CLI and Ollama. It turns one engineering outcome into acceptance criteria, isolated work, post-change tests, independent review and one evidence-backed completion report.

The operator problem

Too many terminals

Parallel agents create branches, prompts and partial results that the operator must reconcile manually.

Unclear “done”

Progress messages, stale tests and model opinions are often mistaken for implemented and verified work.

Weak accountability

Provider identity, writer authority, changed files, tests and unresolved risks are frequently disconnected.

The MC-GPT loop

01

Outcome

Natural language becomes an explicit acceptance contract.

02

Plan

Specialists reason independently and challenge the plan.

03

Build

One authorised writer works in an isolated Git worktree.

04

Verify

Reviewers inspect the post-change diff and deterministic tests.

05

Repair

Failures trigger a bounded diagnosis, repair and retest loop.

06

Report

One brief or complete evidence report states what is finished and what is not.

Who it is for

Agent-heavy developers

People already using several coding CLIs who need clean isolation and one result.

Platform and DevSecOps teams

Teams that need writer authority, audit evidence, post-change tests and rollback boundaries.

Sovereign and on-prem evaluators

Engineers assessing local/cloud model routing, privacy classification and Ollama seats.

Usage

Start with one engineering outcome. Use plan mode for read-only evaluation and inspect the final diff, tests and evidence before any operational decision.

iot-ai status
iot-ai "Review the remaining work and show one brief report; do not execute."
iot-ai "Finish the selected work, use independent review, repair failures, retest and report."
